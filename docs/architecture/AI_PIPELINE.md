## Contract

```text
Video → Topic Screening → Transcription → Claim Extraction → Claim Normalization
→ Claim Classification → Empty Assessment Package
→ Skill-based Judgment → Report Narrative → Saved Report
```

Every stage accepts a typed input, produces a versioned typed output, validates untrusted provider data with Zod, persists enough state for audit/retry, and reports explicit errors. Prompts, schemas, provider/model versions, and evaluation dataset versions should be recorded with analysis metadata.

## Stages

1. **Video:** validate ownership, size, type, and storage reference; never trust file metadata alone.
2. **Topic screening:** videos up to 12 seconds are screened using the full compressed audio track; longer videos use at most three four-second ranges near the start, middle, and end. Mediabunny demuxes/remuxes encoded audio packets without decoding the media. If container metadata omits audio-track duration, duration is computed from packet timestamps. The remuxed sample is capped at 2 MB. Only that sample is sent to OpenAI `whisper-1`; its temporary transcript is classified by `gpt-4o-mini` using strict JSON Schema and Zod validation. A high-confidence off-topic decision is the only result that stops processing. Missing/unsupported audio, unavailable duration, low-confidence output, malformed output, and API errors continue to full transcription. The sample transcript is not persisted; a versioned decision record stores models, instruction version, bounded rationale, reason, confidence, and sample duration.
3. **Transcription:** OpenAI `whisper-1` receives supported MP4/WebM files up to 25 MB. The adapter requests `verbose_json` segment timestamps, validates the untrusted response with Zod, and persists language plus segments under `transcription-v1`. Larger videos currently fail explicitly. See the [OpenAI speech-to-text guide](https://developers.openai.com/api/docs/guides/speech-to-text), [structured outputs guide](https://developers.openai.com/api/docs/guides/structured-outputs), and [GPT-4o mini model](https://developers.openai.com/api/docs/models/gpt-4o-mini).
4. **Claim extraction, normalization, and classification:** OpenAI returns atomic checkable statements with a source excerpt, standalone normalized statement, claim type, and indexes into the input transcript segments. Server code verifies source tokens against those segments (including Russian `ё`/`е` spelling variation), stores the exact transcript excerpt, and derives timestamps from the transcript rather than trusting model-provided timestamps. Original and normalized wording are both persisted. A failed repair logs only the validation category and job ID, never transcript or model text.
5. **Assessment package:** the Worker creates and persists an empty package with `psychology-skill-no-search-v1` and `no-reranking-v1`. It records `scientific_search_not_performed`; it does not query Europe PMC, Crossref or a local corpus. Package persistence remains idempotent and uses the existing run-fenced workflow boundary.
6. **Judgment:** `fact-check-judgment-v8` applies `psychology-evidence-check-v4`, a server-side implementation based on the local skill. For an empirical claim with the no-search package, the server enforces scientific `unknown`, `insufficient` evidence strength, low confidence, and app verdict `INSUFFICIENT_EVIDENCE`; normative and metaphorical assessments map to `not_empirical` / `UNVERIFIABLE`. Citations remain empty. The separate `modelVerdict` and its wording analysis remain visible as a preliminary model assessment, not a source-based conclusion. Prompt, model, judgment and output-schema versions are persisted. Retry, run fencing and immutable citations are unchanged.
7. **Citation storage:** current no-search judgments have no citations. Historical citations continue to resolve against their original owner-scoped packages.
8. **Explanation:** state the comparison, qualifications, uncertainty, and citations using only package identifiers.
9. **Report narrative:** after all immutable fact checks are saved, a separately versioned provider receives only validated Evidence Packages and their validated judgments. It writes a short model commentary per claim, a video-level conclusion, and a clearly labeled subjective opinion. The general conclusion distinguishes conflicting, limited, and insufficient evidence; missing publications never count as refutation. The subjective opinion is not evidence and cannot change a saved verdict. Narrative output has no citations; its claim IDs are schema-checked and its artifact is fenced to the active workflow run.

## Report language

Normalized claim formulations, judgment explanations, limitations, and citation rationales are requested in Russian. Exact transcript excerpts and bibliographic source metadata remain in their original language. When a saved judgment is in another language, the report view translates only the normalized formulation and explanation, validates the returned fact-check IDs and Russian text, then caches the rendering in `report_localizations`; immutable verdicts, evidence packages, and citations are not rewritten. The cache is owner-readable and populated through an authorization-checking database function.

## Judgment responsibility

Judgment answers: **Given only this Evidence Package, how does the evidence bear on this normalized claim?** It cannot search, rely on unstated model knowledge, or cite identifiers outside the package. It must distinguish no evidence from contradictory evidence, association from causation, theory from established fact, and historical views from current consensus.

The report narrative is a separate presentation artifact, not another judgment. Its commentary is subjective, uncalibrated, and must never be presented as scientific evidence. The artifact stores generated text and provider/model/prompt/schema versions, not copies of evidence passages.

New results include the skill verdict, claim type, categorical evidence strength and assessment confidence, a bounded explanation, caveats, cited chunk IDs, and what additional evidence is needed. The report places those categories in the existing judgment summary block; historical reports keep their numeric confidence display. Code validates the schema and package membership. A structural success is not automatically a factual success: model quality remains unconfirmed until expert-reviewed golden cases exist.

The product does not perform a literature search, so no scientific coverage is claimed. The skill's method is encoded as a versioned server prompt because a local Codex skill file is not available to the deployed Worker at runtime; the Worker does not invoke Codex skills directly. Model quality is not established without expert-reviewed golden cases.

## Failure and retry policy

Screening is a cost-saving prefilter, not a truth or claim-extraction stage. Only a validated `unrelated` result at or above the 0.9 confidence threshold with an allowed out-of-scope reason stops processing; every other result fails open. Screening metadata is unique by content item and screening version, so a later workflow generation reuses it. The expanded topic classifier uses `topic-screening-v2`. If a transcript already exists, the workflow bypasses screening and proceeds to claim extraction. A completed job whose initial screening was uncertain is not re-screened by retry; upload the video again to validate a screening-code change. Invalid screening output is recorded as uncertain and never silently accepted. Claim extraction artifact v2 uses schema `claim-extraction-schema-v1` and Russian instructions `claim-extraction-instructions-v4`: it seeks all distinct checkable claims directly relevant to the declared topic scope, including claims that may have no matching publication, and omits unrelated factual statements. Historical v1 extractions remain readable; a retry of an unfinished job creates v2 once, with no migration. The provider permits one repair call for malformed or transcript-inconsistent output. It caps transcript text at 100,000 characters and claim output at 100 items; overlong transcripts fail explicitly rather than being truncated. Extraction rows, including empty-result markers, are saved idempotently. Provider timeout/rate-limit errors may retry with bounded exponential backoff. Stage outputs use idempotency keys so workflow retries do not duplicate transcripts or claims.
